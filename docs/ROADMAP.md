# Voica — план на будущее

Заметки по нереализованному и по решениям, которые приняли сознательно. Что уже вышло —
в [CHANGELOG.md](../CHANGELOG.md); здесь только то, что впереди, и то, что решили НЕ делать
(чтобы не возвращаться к вопросу с нуля).

Актуально на 0.9.11 (август 2026). Windows-порт (`Inhum/voica-win`) идёт своей нумерацией и
на 0.6.0 закрыл матрицу паритета — см. [CORE-SPEC.md](CORE-SPEC.md).

## Дистрибуция и подпись

- Сейчас: подпись локальным **self-signed сертификатом** «Voica Self-Signed»
  (`scripts/make-cert.sh`, ключ в login keychain). Даёт стабильную идентичность →
  разрешение Accessibility держится между обновлениями. Но сертификат не доверенный
  системой, поэтому на чужом Маке первый запуск — System Settings → Privacy & Security →
  **Open Anyway** (или `xattr -dr com.apple.quarantine /Applications/Voica.app`).
- **Один сертификат на все Маки.** Отпечаток зашит в подпись; macOS привязывает к нему грант
  Accessibility. Если собирать релизы на другом Маке с *другим* сертификатом — у пользователей
  грант слетит. Экспортировать `.p12` (Keychain Access → «Voica Self-Signed» → Export) и
  импортировать на все машины сборки, включая CI.
- **Бэкап `.p12` обязателен.** Потеря сертификата = все пользователи один раз заново выдают
  Accessibility.
- **Нотаризация и Apple Developer — РЕШЕНО НЕ ДЕЛАТЬ** (до 1.0 точно). Причины: $99/год плюс
  статус developer, недоступный гражданину РФ. Следствия принимаем: «Open Anyway» при первом
  запуске (документировано в README и FAQ сайта) и невозможность полноценного Sparkle-апдейта.
  Windows: сертификат ~$100–400/год либо Azure Trusted Signing — тот же вопрос, тот же ответ.

## Авто-обновления

**Проверка обновлений сделана** (вкладка About): приложение анонимно читает GitHub Releases,
сравнивает версии, показывает кнопку «Скачать». Ничего не качает и не ставит само.
Прежний раздел про «подвох приватного репозитория» снят: репозиторий публичный, родные
GitHub Releases работают анонимно.

Осталось «сам обновился»: **Sparkle** (macOS) или **Velopack** (macOS + Windows из одной
системы). Оба требуют настоящей подписи, поэтому упираются в решение выше — **после 1.0**,
если вообще.

## Кросс-платформенность

**Windows-порт существует** (`Inhum/voica-win`, C#/.NET 8 + WPF, локальный движок на ONNX
Runtime) и по фичам догнал macOS. Выбор в пользу двух нативных баз вместо одного
кросс-платформенного кода оказался рабочим — при условии, что паритет держится документом.

**Правило паритета (действует):** сначала правится [CORE-SPEC.md](CORE-SPEC.md), потом фича
зеркалится во вторую реализацию. В локстепе держим **набор фич**, а не номера версий —
платформы нумеруются независимо, «1.0» у каждой своя. Матрица паритета в конце спеки.

**iOS — отдельный проект и не в планах.** Глобальных хоткеев нет; путь был бы через кастомную
клавиатуру или share-extension, то есть другой продукт.

## Живая диктовка — текст появляется по ходу речи

**Запрошена пользователями** (пришло со стороны Windows-порта, разбор —
[voica-win/docs/ROADMAP.md](https://github.com/Inhum/voica-win/blob/main/docs/ROADMAP.md)).
Фича кросс-платформенная, поэтому по правилу паритета живёт и здесь.

Сегодня Voica **пакетная**: записали целиком → отправили → получили финальный текст (§2, §3
спеки). Показать текст по ходу фразы такая схема не может конструктивно — модель видит только
законченную запись.

Нужен **стриминговый ASR** с промежуточными гипотезами: звук уходит кусками (обычно по
вебсокету), текст постепенно вставляется и уточняется.

- **Облачные стриминговые STT:** Deepgram, AssemblyAI Realtime, Azure / Google streaming,
  OpenAI Realtime. У **Groq стриминга нет** — значит живой режим потребует другого бэкенда,
  выбираемого в настройках, а пакетный Groq остаётся по умолчанию.
- **Локально:** whisper.cpp в стриминговом режиме, Vosk; у NVIDIA стриминг — Parakeet / Canary
  (через NeMo / Riva). GigaAM в нынешнем виде не стримит: окно фиксированное, 25 с.

**Главная сложность — не распознавание, а вставка.** Промежуточную гипотезу приходится
**заменять** в уже заполненном чужом поле, а универсального «удали последние N символов» в
приложениях не существует. Варианты: живой режим только в окне результата; аккуратный
backspace через синтетические нажатия; отдельный оверлей поверх экрана. Плюс выбор провайдера
и компромисс «задержка против цены» в настройках.

## Диаризация («кто говорит») — разобрано, отложено

Возникает только внутри файловой транскрипции: у диктовки говорящий один, размечать нечего.
Разбор от 2026-08-14, чтобы не начинать заново.

**Решение: не делаем.** Граница проведена так: **файловая транскрипция — да, диаризация — нет.**
Расшифровка файла остаётся тем же движением, что и диктовка, только источник звука другой
(надиктовал в диктофон, прислали голосовое, записал лекцию) — и говорящий там по-прежнему один.
Как только появляются «спикер 1» и «спикер 2», это уже инструмент для совещаний: следом
попросят таймкоды, субтитры и резюме встречи. Это другой продукт и чужая территория.

**Если всё же вернёмся — путь известен.** Технических блокираторов нет.

- Связка «GigaAM + pyannote» ничем не хуже привычной «Whisper + pyannote»: диаризация работает
  **только со звуком** и про распознаватель не знает вовсе. Два независимых прохода по файлу,
  потом склейка по времени.
- Конвейер: VAD/сегментация → эмбеддинги голоса → кластеризация. Третий шаг — обычный алгоритм
  на Swift, ни весов, ни зависимостей.
- **Python пользователю не нужен.** Тяжёлое окружение (torch, coremltools) требуется один раз
  на машине разработчика, при конверсии — ровно как это уже было с GigaAM. В приложение едут
  готовые `.mlpackage`. Модели маленькие: сегментация — единицы мегабайт, эмбеддер — пара
  десятков, суммарно порядка 30 МБ (проверить перед работой). Их можно даже класть в бандл,
  не докачивая. Архитектуры свёрточные, то есть заметно проще GigaAM.
- Запасной путь, если конверсия не пойдёт: **`sherpa-onnx`** — диаризация там уже собрана на
  готовых ONNX-моделях. Плата — библиотека рантайма в бандле и счёт на CPU вместо ANE. Для
  разбора файла это приемлемо: режим не real-time.
- **Тайминги слов у нас уже есть, просто выбрасываются.** CTC отдаёт по кадру на каждые 40 мс
  звука (мел-кадр 10 мс, энкодер сжимает вчетверо: 2499 кадров на входе → 625 на выходе).
  Достаточно перестать терять индекс кадра при схлопывании повторов — выравнивание получается
  без единой новой модели.

**Лицензии проверены 2026-08-14 — блокираторов нет:**

| Модель | Лицензия | Гейт на HF |
|---|---|---|
| `pyannote/segmentation-3.0` | MIT | да (нужны контакты) |
| `pyannote/wespeaker-voxceleb-resnet34-LM` | CC BY 4.0 | нет |
| `pyannote/speaker-diarization-community-1` | CC BY 4.0 | да |

Все три разрешают коммерческое использование и распространение весов в составе приложения.
Гейт — про доступ к скачиванию, а не про лицензию. **CC BY 4.0 требует указания авторства**:
запись в `THIRD-PARTY-LICENSES.md`, и атрибуция обязана ехать вместе с весами, если публиковать
свою конверсию. **Отдельная оговорка:** эмбеддер обучен на VoxCeleb, лицензия
унаследована от датасета, а сам VoxCeleb исторически раздавался с оговоркой про
исследовательское использование — известная серая зона. Для бесплатного открытого приложения
риск нулевой; в сценарии, где веса раздаются в составе продаваемого продукта, вопрос
происхождения датасета зададут — нужен готовый ответ или другой эмбеддер.
